# AGENTS.md

Instructions for AI coding agents (Claude Code, Codex, Cursor, or any other LLM-based tool) working in this repository.

## What this is

SECourses Musubi Trainer — a Gradio GUI (`musubi_tuner_gui/`) wrapping the vendored `musubi-tuner` training backend (`musubi-tuner/`) to train LoRAs and full fine-tunes for Qwen Image, Qwen-Image 2.1, Wan 2.1/2.2, FLUX / FLUX.2 / FLUX Klein, FLUX.3 Klein, MOSS-Image, Z-Image, Ideogram 4, Krea 2, ERNIE-Image, Mage-Flow / Mage-Flow-Edit, HiDream-O1, LTX 2.3, MiniMax H3, and Kandinsky 6. `README.md` is the user-facing feature tour (screenshots, install instructions, marketing); this file and `AI_TRAINER_GUARDRAILS.md` are for people/agents changing the code.

## Read this before adding a new trainer tab or model

**`AI_TRAINER_GUARDRAILS.md` documents mistakes already made once in this codebase and fixed — read it before adding or modifying a trainer tab.** They're easy to reintroduce when copy-pasting an existing `*_lora_gui.py` as your starting point, because each bug only surfaces later, in a scenario a quick manual test won't hit:

1. **Logging paths** — an empty `logging_dir` reaching the runtime TOML silently becomes a filesystem-root path on the backend.
2. **Training-mode round-trip** — if the new trainer supports both LoRA and Full Fine-Tuning, `training_mode` must be persisted in the runtime TOML and correctly re-inferred when loading an older TOML that lacks it. Get this wrong and reloading a saved/failed full-finetune run silently retrains it as LoRA instead, with no error shown.

Update `AI_TRAINER_GUARDRAILS.md` with a new guardrail (same format: Rule / Why this exists / Required implementation pattern / Regression check) any time you fix a bug in this codebase that a future "add a new model" pass could plausibly reintroduce.

## Architecture map

- `gui.py` — builds the **unified UI** (`musubi_tuner_gui/unified/`, see below) by default; `python gui.py --classic` instead mounts each trainer's own `*_tab()` function, grouped as **Image Models / Video & Audio Models / Tools / Version History** (nested `gr.Tabs`; Gradio renders tab children lazily). The unified registry (`unified/registry.py`) is the source of truth for which models are live.
- `musubi_tuner_gui/image_models_gui.py` — the **spec-driven** trainer for the newer models: Qwen-Image 2.1, ERNIE-Image, Mage-Flow (T2I + Edit), FLUX.3 Klein (T2I + editing), MOSS-Image, HiDream-O1 and Kandinsky 6 (video+audio). Each model is one `ImageArchSpec` (scripts, `ModelPath`s, `ExtraOption`s, cache-argument builders, validation hook, defaults); the UI, save/load, presets, runtime TOML and command building are shared. **To add another image/video model, add a spec here** rather than copying a `*_lora_gui.py`. Components are registered by key (`reg()`) and the tab build asserts the registered keys equal `param_keys(spec)`. Tests: `tests/test_image_models_gui.py`.
- `musubi_tuner_gui/preset_library.py` — the **⚡ GPU preset picker** shown under every trainer's configuration bar. Presets live in `<install root>/Training_Presets/<Model>_Training_Configs/{LoRA_Training,Fine_Tuning_Training}/<GPU>_GB_GPUs_<measured peak>_GB*.toml` (`preset_roots()` also reads `<install root>/<Model>_Training_Configs`, where older releases kept them); `MUSUBI_PRESETS_DIR` overrides both. *Apply Preset* writes the path into the tab's config dropdown and then runs that tab's own Load handler (`PresetLibrary.bind`). Shipped presets are read-only: Save refuses to overwrite files inside `*_Training_Configs` (`is_shipped_preset`).
  The shipped tier presets are produced by the VRAM lab in `<install root>/dont_upload/vram_lab/` (not shipped): `measure.py` runs a preset through the owning tab's own print-command path (its dataset TOML adds `control_resolution` for specs with `references_keep_framing`, as the GUI does) and samples `nvidia-smi` every 100 ms (its s/step is the steady rate from the training bar, `measure.steady_sec_per_step`: from the first step the bar shows to the last, without the end-of-training save; until 2026-10-21 it took tqdm's closing line, which averaged a fine-tuning save into the 3 measured steps (MOSS-Image 32 GB: 13.61 for 3.5 s steps) and in the LoRA loop counted one step too many (MOSS-Image LoRA 32 GB: 1.65 for 2.02 s steps); `restate_speeds.py` restated the shipped presets from their logs; it waits for an idle GPU 0, writes fresh-cache measurements into a run-specific folder, trains from one cache folder per resolution / frame count — `cache_dir_lab_<W>x<H>[_f<frames>]` — because training loads every `*_<arch>.safetensors` in its cache folder and image cache files are named by the *source* image size, so a shared folder silently reuses or mixes other resolutions' latents, and treats 15 s at the card's total as a WDDM spill/OOM); `autotune.py` searches, per tier, the least block swap of each quality candidate that stays under `tier - 1.5 GB` (a candidate can carry its own `max_swap` and `skip_swaps` where the backend's offloader modes differ) and writes the preset, superseding any older preset of that tier; `make_jobs.py` defines every model's quality ladder and cache options; `queue_runner2.py` runs jobs from `queue2/` one at a time; `make_readmes.py` writes each folder's README table. The lab reads and writes the presets in `<install root>/Training_Presets/` (`PRESETS` in each script; `jobs/*.json` `out_dir` and `tier_report.jsonl` paths point there); the server copy keeps the older `<root>/<Model>_Training_Configs` layout, which `pull_remote_results.py` maps onto `Training_Presets` (jobs made there with the current `make_jobs.py` write `<root>/Training_Presets/<Model>_Training_Configs`; the pull reads both). `fix_headers.py` runs first, after every pull, because the pull restores the server's files. It normalizes the description lines and caps checkpoint saving at every 25 epochs, keeping only the newest training state. The V34 demo bases saved every epoch for 200 epochs, full fine-tuning with its optimizer state. On a multi-GPU Linux machine, `queue_worker.py --gpu N` (one per GPU) claims jobs from `queue_multi/` atomically (`LAB_GPU` pins the trainer, its caches and the sampling to that GPU; jobs can require downloaded model bundles and free RAM), and `pull_remote_results.py` copies the server's presets and tier records back (folders measured on the server are mirrored; folders measured here only take the tiers the server re-measured). Stop a queue job only with `stop_job.sh <queue name>`: it stops the autotune before its measure and training processes, so a stopped step is never recorded in the job state as a failed configuration. `release_held.sh` moves RAM-heavy jobs from `queue_hold/` into the queue one at a time, because a worker checks free RAM only when it claims a job. After a change that affects every preset (DoRA in the LoRA presets, a library upgrade), `verify_presets.py queue [--fresh-cache] [--kohya-files JSON]` / `work --gpu N` / `report [--write]` re-measures every shipped preset as shipped (kohya FLUX.1 presets through `kohya_smoke.py`; a worker claims a job only with `--min-free-gb` free RAM and prefers the model with the fewest running jobs; `--fresh-cache` re-encodes the caches with the current libraries and removes them afterwards). A state file copied from another machine is reused as long as its results name the GPU they were measured on (`gpu`/`platform`/`peak_offset`). Linux reads 0.37-0.47 GB less than Windows for identical runs (RTX A6000 vs RTX 5090), so `autotune.py` adds a 0.5 GB Windows allowance to Linux measurements (`LAB_PEAK_OFFSET_GB`); each preset names the GPU it was measured on. Never run other GPU work (tests, GUI training) while the queue measures. To keep tests on the CPU set `CUDA_VISIBLE_DEVICES=-1`: an empty value hides nothing on Windows (PowerShell deletes the variable; from bash torch reports 0 devices until CUDA initializes, then sees every GPU, so CUDA-gated tests still run on GPU 0).
- `musubi_tuner_gui/class_tab_config_manager.py` — `TAB_DEFAULT_FILES` is the single registry of tab name → defaults TOML; add new tabs there only.
- `musubi_tuner_gui/*_lora_gui.py` — one file per trainer (e.g. `qwen_image_lora_gui.py`, `wan_lora_gui.py`, `zimage_lora_gui.py`, `modern_image_lora_gui.py` for Ideogram 4 + Krea 2). Each defines the tab's UI, a `train_*_model()` function that builds the launch command and writes the runtime config TOML, and `open_*_configuration()` / `save_*_configuration()` for the Load/Save buttons.
- `musubi_tuner_gui/common_gui.py` — shared infra, including `SaveConfigFile()` (💾 Save button, hand-managed presets) and `SaveConfigFileToRun()` (the actual runtime TOML written to `output_dir`, the one passed to the backend via `--config_file`). These two paths have different exclusion rules — check both when changing what a trainer persists. The backend reads runtime TOML values without argparse conversion, so their types matter (Guardrail 15). Importing the package runs `toml_compat.install()` (`musubi_tuner_gui/__init__.py`): toml 0.10.2's own string writer produced invalid TOML for any path containing `\x` (`C:\Users\xavier\...`).

Wan and MiniMax H3 don't use it: Wan's full-finetune mode is disabled in the UI (there is no full-DiT Wan script), and MiniMax H3 has no full-finetune script upstream.
- `musubi_tuner_gui/minimax_h3_lora_gui.py` — MiniMax H3 T2VA/FL2VA/Ref2VA video+audio LoRA tab, modeled on the LTX-2 tab (canonical `MINIMAX_H3_PARAM_KEYS` list, `prepare_minimax_h3_workflow` builds latent-cache → TE-cache → train commands). The fork applies H3's RoPE elementwise (upstream #1156; the 2x2 matmul ran as GEMV launches) in place (`minimax_h3/model.py::_apply_rope_split_half`: four FP32 copies of the rotated half instead of six, bit-identical; the upstream form read +0.34 GiB on the 10 GB preset, the in-place one fits every tier, 1.2-1.6x faster steps on an A6000), and Ref2VA video references hand the processor a bare `<|video_pad|>` (#1157: transformers 5 adds the markers itself). LTX-2 training-time sampling loads the text connectors, VAE and audio models with `ltx_2/loader/sft_loader.in_process_checkpoint_loader()` (plain file reads): safetensors 0.8 cannot map the single-file checkpoint a second time while the training DiT holds tensors mapped from it (CUDA open: "invalid python storage", CPU open: process crash), which stopped every LTX run with samples at its first sample. Backend tests: `PYTHONUTF8=1 PYTHONPATH=src python -m pytest tests -c pyproject.toml --rootdir .` from `musubi-tuner/` (UTF-8 mode matters on Windows: some tests decode subprocess output). ## Unified UI (`musubi_tuner_gui/unified/`)

- `app.py` builds five tabs: 🖼️ Image / 🎬 Video / 🔊 Audio Models, 🧰 Tools, 📜 Version History. Each model tab is one `Workspace` (`workspace.py`): step cards (base model → LoRA / Fine-Tuning → GPU preset), model card with tips (`hints.py`), settings sections, Start / Stop / Print Command and the live monitor. A trainer module that fails to import only removes its models; a category left without any shows an error card instead of stopping the app. The open tab is remembered in `ui_state.json` (`last_category`) only from selects that carry the browser's user activation (`USER_ACTION_JS`: Gradio itself selects the first tab when a page opens) and a load handler re-selects it; `remember_selection` never writes it (every workspace re-applies its selection on page load). `--headless` drops the 📂 / 📄 browse buttons (no file dialog on a server).
- Trainers are not re-implemented. `legacy_tabs.py` lists the 13 musubi trainer modules and `backends.py` calls each module's own `*_gui_actions` (load, save, print command, train) with values in the module's positional order; FLUX.1 and SDXL run on kohya sd-scripts through `kohya_backend.py` (the `sd-scripts` clone, FurkanGozukara/sd-scripts-premium; folder-mode runs pass `enable_multiline_caption` (kohya 31236c8, ported), without which sd-scripts trains on a caption file's first line only while the musubi trainers read the whole file; V37 adds input-axis DoRA and fixes `flux_utils.load_flow_model`, whose `fp8_scaled` path kept every quantized weight on the GPU with block swap: `move_to_device=True` means "keep it on the calc device", so it must be `loading_device.type != "cpu"`; the 12-24 GB FLUX.1 LoRA presets stream their swapped blocks H2D-only, `block_swap_h2d_only` from sd-scripts #2467, with 3-4 more blocks than the classic swap at the same VRAM (`vram_lab/run_flux1_h2d_eqvram.sh`, applied by `kohya_flux1_h2d_apply.py`; at an equal block count it took 1.1-1.8 GB more) and 41-81% faster steps on an RTX A6000 (`run_flux1_h2d_recheck.sh`: old / new / old on a quiet GPU, steady steps, the faster classic time; notes restated by `kohya_flux1_h2d_restate.py`; the first 55-99% came from a loaded host; kohya's own 11.7 → 9.4 s/step, +24%, is MOSS-Image at an equal 36 blocks on an RTX 3090 at PCIe Gen3 x4). `registry.py` maps every model the user sees (`ModelEntry`: category, icon, modes, preset folders, fixed variant values such as the FLUX.2 family) to a backend.
- `legacy_schema.json` holds every trainer's settings (keys in positional order, labels, defaults, choices, bounds), recorded by building each classic tab headlessly, plus `arg_types`: the argparse type / nargs of every setting the training scripts read (`tools/trainer_arg_types.py` captures each script's real parser from its own `main()`, CPU only). **Regenerate it after changing a trainer's settings or pulling training-script changes into the fork:** `venv\Scripts\python.exe tools\generate_unified_schema.py`; `tests/test_unified_ui.py::test_schema_matches_the_trainer_modules` fails while it is stale. `schema.py` places keys into sections (`SECTION_KEYS`, `ADVANCED_KEYS`, `LORA_ONLY_KEYS` / `FULL_ONLY_KEYS`); unlisted keys are placed by name.
- Presets (`presets.py`): shipped presets are read-only; user presets are saved by name to `<install root>/user_presets/<model>/` or to any full path, with a `preset_*` metadata header that `identify_preset` uses for the guardrails (a preset of another category is refused, another model or training type is switched to). Last selections live in `user_presets/ui_state.json` (read and written under one lock; a damaged file is ignored, never fatal). A preset that cannot be read is refused when the user picks it (selector and settings stay as they were) and replaced by the defaults, and forgotten, when it was only remembered. `ui_state.json`'s GPU tier only applies where the model offers it (`offered_tier`); the training type of a shipped preset comes from the folders below its `*_Training_Configs` folder, never from the install path; kohya_ss DreamBooth configs (no LoRA keys) load as Fine-Tuning; a name such as `my run.toml` is a preset name, and Load finds a name by the same cleaning Save used. Tests must set `MUSUBI_USER_PRESETS_DIR` so they never write the real state file.
- Values (`values.py`): the trainers load the runtime TOML with `parse_args(namespace=...)`, which converts nothing, so a `1.0`, a `"1e-4"` or a quoted path would reach the training code as written. Every value is converted to its argparse type and paths are cleaned (quotes, padding, line breaks, `/` vs `\`, `%VAR%`, `~`, `file:///`; Hugging Face repo ids and URLs stay as typed) in `Backend.coerce`; `Backend.check` lists unusable input by label for Start / Print Command; `enforce_trainer_types` wraps `common_gui.SaveConfigFileToRun` during unified runs, so classic-tab quirks cannot change types (Qwen Image collapses list options to their first item). Whole-number settings read `10,000` as ten thousand, decimal settings read `1,004` / `0,0001` as decimal commas. Multi-path settings (`base_weights`) use the classic syntax: one per line or `;`, or several on a line with quotes around paths with spaces (an unquoted line splits only where another absolute path starts); the UI shows them that way. Text of several lines is never cleaned as one path (kohya's Sample Prompts takes prompt text). A loaded value is the classic loader's, except path lists a classic loader joined with plain spaces (taken from the file). Blank is valid where 0 is the default or the trainer's own default is None (Wan reads a saved 0 back as blank there); `schema.ZERO_MEANS_UNSET` settings write 0 as "not set" (Max Timestep 0 would train without noise) and `schema.ARG_TYPE_OVERRIDES` records where a TOML value means something else than the command line (Wan's `timestep_boundary` ≤ 1.0 is a fraction). Whole-number settings (`Backend.whole_number`: int arguments, classic `precision=0` numbers, the classic modules' `*_INT_KEYS` and `schema.WHOLE_NUMBER_KEYS` counts such as ports and batch sizes) read `18,343` as eighteen thousand and refuse fractions; `lr_warmup_steps` / `lr_decay_steps` stay a fraction only below 1 (musubi reads any float as a ratio). Save refuses what `Backend.check_values` reports (a classic save would store it changed). `tests/test_unified_presets_roundtrip.py::test_messy_input_survives_save_load_and_the_ui` fuzzes every setting of every model (`UNIFIED_FUZZ_SEEDS=40` for a deeper run). Mode switches without a preset apply the classic tabs' mode recipes (`_mode_recipe`: LTX 2.3 fine-tuning, Ideogram 4 block-swap limit). Tests: `tests/test_unified_values.py`, `tests/test_unified_runtime_toml.py` (every model and training type, messy input, real runtime TOML checked against argparse).
- Datasets (`dataset_tools.py`): Start builds the dataset TOML with each trainer's own generator and hands it over through `generated_toml_path`. In folder mode `generated_toml_path` and `dataset_config` are cleared first and `generated_toml_path` is never saved in a preset: the classic train code reuses that file whenever it exists, which trained an old folder. When `prepare_dataset` built the run's TOML itself (audio clips, mixed folders) the run switches to "Use TOML File" (`_hand_over_dataset`), so the classic train cannot regenerate a different one. 🔍 Check dataset (`dataset_inspector.py`) walks the folders (or a dataset TOML's `[[datasets]]` / kohya `[[datasets.subsets]]`) with the trainers' own rules: musubi's media extensions and exact-stem captions (strict UTF-8, as the trainers read them), its control-image pairing (`photo.png` -> `photo.png`, `photo_0.png`, …; longest name first; any other text after `photo_` stops caching), which generator owns a control folder (`control_settings`: Krea 2 / Ideogram 4 / Z-Image never), sd-scripts' `<repeats>_<class>` folders and regularization images for kohya, the image size as stored (EXIF rotation is ignored by the trainers) and a decode of every probed file. It renders stat cards, problems with example files, a folder table and distributions, and gallery previews (edit pairs side by side, a video's first frame, an audio waveform) cached in `%TEMP%/secourses_dataset_previews` (at most 400 files, written atomically, with a time budget). Tests: `tests/test_unified_datasets.py`. Folders with images and videos also train their images (Wan, LTX 2.3 video mode, Kandinsky 6; the classic generators keep only the videos); MiniMax H3 is video only; LTX 2.3 audio mode uses audio clips and the audio of videos (extracted with PyAV to WAV under `<cache>/extracted_audio`, captions copied; never a sub-folder of the dataset folder itself, which the video generators would skip). Tests: `tests/test_unified_datasets.py` (tiny real media from `tests/media_fixtures.py`).
- Training (`runner.py`): `TrainingRunner` replaces each module's executor, parses tqdm / epoch / checkpoint lines into a bounded snapshot (≤480 chart points, last 600 log lines), finds the run's GPU from nvidia-smi per-process bus IDs and writes the full log to `logs/training_runs/`. `metrics_hook.py` (loaded by `sitecustomize.py` when `SECOURSES_LIVE_METRICS=1`) adds the optimizer's live `lr=` to the steps bar. `monitor.py` polls the runner from the browser through `gr.HTML(server_functions=...)`; it closes a stop question once no run is active and keeps the latest download log until its box is on the page (Model Files is not rendered while collapsed). `downloads.py` marks a download stopped before killing it, so its log ends "stopped", not with the kill's exit code.
- Performance rules (each Gradio 6.30 update walks the whole page on the client and a workspace has ~200 settings): no `gr.Timer` (one tick costs ~0.7 s of main-thread time here); show and hide settings with CSS from `data-*` attributes on the workspace root (`Workspace.generated_css`), never with `visible=` updates (the Download row follows `data-dl`; the banner and the preset description hide while empty with `:has()` rules); send only changed values (`Workspace.emit` diffs against a per-session mirror); give events `show_progress_on=[sink]` and minimal inputs. `queue=False` events cannot show `gr.Info` / `gr.Warning` toasts. One session's events run one at a time (`Workspace.session` lock); model / training type / tier / preset selectors use `trigger_mode="always_last"` (the default drops a second quick click); the state JSON carries a `seq` so every switch re-applies the rule attributes; a no-change result must name one of the event's own outputs (`emit` does). There is no `demo.unload` hook: mirrors are an LRU of `MAX_SESSIONS`. Sliders record user edits with `.input` and `trigger_mode="always_last"`, never `.change` (it also fires for every value a switch sends: one request per slider while the switch renders). The ⚡ VRAM panel (`vram_advice.py`) compares the fields in `vram_advice.WATCHED_KEYS` with the values of the last load (stored per session by `apply` and `restore`) and the preset's measured peak from its file name; it sticks to the bottom of the page, which needs `.gradio-container { overflow: clip }` (Gradio's `hidden` disables every `position: sticky`). Gradio 6 wraps consecutive fields of a row in a `.form` box and resets their min-width to 0: `unified.css` restores it for `.check-grid` / `.field-grid`. Tests: `tests/test_unified_vram.py`. A `gr.Number` emptied by the user sends `null`, but one emptied without an input event keeps its last value: `STATE_JS` refills required numbers on blur (and fires `input`) so the screen and the server agree.
- Value links (`links.py`): the unified UI does not run the classic tabs' Gradio events, so a classic `.change` / `.input` handler that sets another setting's value must be mirrored as a `Link` (HiDream-O1 model type → checkpoint, noise schedule, CFG; HiDream task → control images; Mage-Flow Edit → its own checkpoint; Wan FP8 Base → FP8 Scaled; Wan task → compile residency; Klein version → sample steps / guidance; frame counts rounded to each VAE's grid). The workspace records the trigger and follows its links in one handler; a link also runs at load time when the model entry fixes its trigger, or sets it by default without a preset. A model-file link switches between variant files by name (next to the current file or in the model folder) and clears the path when the target file is missing, never training the other variant's checkpoint. Tests: `tests/test_unified_links.py`.
- 🏆 Best Checkpoint Finder (`checkpoint_finder.py`, scoring in `musubi_tuner_gui/best_checkpoint/`): image and video categories only (`CF.available`). Its default test prompts follow the subject's class word (`prompts.default_prompts`: the SECourses person set is written for a man, a woman gets her pronouns, a person of unstated gender theirs with agreeing verbs, any other class word, a dog or a toy, the object set and a park-bench leakage prompt); a subject change replaces prompts that are still the previous subject's defaults (`CF.prompts_for_subject`), edited prompts only get the new subject. Its settings (on/off, subject, prompts, seeds per prompt, leakage check) are remembered per category in ui_state.json (`best_checkpoint`) and saved with a user preset as the `preset_best_checkpoint` header line (JSON in a TOML string, `P.write_metadata_header(extra=...)`); a user preset the user loads applies them (`apply(finder_from_preset=True)`), a shipped preset keeps the current ones, and kohya loads ignore every `preset_*` key. Start calls `CF.prepare_run` after the `_last_run` autosave (which keeps the user's own sampling): it needs Save Every N Epochs or Steps (it samples at the step saves when the epoch saves give only the final model: the SDXL fine-tuning presets train 1 epoch and save every 451 steps), writes `<output_dir>/best_checkpoint/<output_name>/{sample_prompts.txt, settings.json}` (one line per prompt and seed with `--d`, kohya lines also with `--w` / `--h` of the training resolution because sd-scripts samples a line without them at 512 x 512; the user's own sample prompts follow and are not scored), sets Sample Prompts, Sample Before Training and the sample interval to the save interval, and passes a `runner.AfterStep` to `RUNNER.start_job(after=...)`. When the training process exits 0 the runner runs `python -m musubi_tuner_gui.best_checkpoint.worker` as the `score` stage (shown only for such runs; Stop ends it; its failure never fails the training), then reads `report.json` into the snapshot's `result` (the dashboard's 🏆 card; its button opens the section's 📊 Show results). 🔍 Analyze runs the worker alone (`RUNNER.start_after_step`). Edit models and MOSS-Image control adapters (control images required) skip it. The worker indexes musubi / sd-scripts sample names (`samples.py`: epoch or step points, `e000000` = base model), scores with YuNet + SFace (OpenCV Zoo), DINOv2-base and SigLIP2-so400m (downloaded on first use to `<install root>/Training_Models_Checkpoint_Finder`, `MUSUBI_FINDER_MODELS` overrides) and ranks with `ranking.py` (thresholds from `dont_upload/best_checkpoint_research`). Prompt following and colour / sharpness are compared with the base model's sample of the same prompt and seed (`summary["vs_base"]`, `scoring.paired_change`): a run's prompts differ far more from each other than a checkpoint changes them, and medians over all samples flagged every Krea 2 checkpoint for a 41% sharpness drift that no single prompt showed. SigLIP2 reads 64 tokens, so a long prompt is scored as sentence groups (`prompt_chunks`, mean). A last checkpoint whose samples are still being written (Analyze during sampling) is left out and named in the reasons; leakage (the class prompt looking like the subject) is one note for the run, not a flag on every checkpoint. Cached scores carry `scoring.SCORES_VERSION`: raise it when a signal changes. The rule (`ranking.rank`, calibrated on 158 research runs of image and video models and objects judged by eye, seed replicates included, 148 picked in the judged range: `dont_upload/best_checkpoint_research/truth_krea2.json` and `truth_general.json`, checked with `calib_all.py` / `calibrate_rule.py`): the knee is where the smoothed face-match gain and the identity margin (training faces minus the base model's face of the same prompt and seed, `scoring.identity_margin`: SFace rates a base-model face that took the subject's glasses 0.6+) both reach 85% of their highest; the onset of over-training is the first checkpoint with a flag, the earliest reliable one being framing (paired face area x1.3 towards the training photos' framing); the pick is the earliest checkpoint within 5% of the most likeness from the knee to the onset (an onset before the knee: the longest run of consecutive clean checkpoints with 70% of it whose faces have left the base model's person, smoothed identity margin 0.10, the earliest of equal runs, so a lone clean save among signs is not their end; an undertrained run: its latest checkpoint without flags among those with `ranking.LEARNED_SHARE` 0.25 of the highest likeness gain and of the identity margin's rise, none: the one with the most likeness, as a clean save that is still the base model is no pick). A kind of sign counts only when it recurs at half of the saves after its first one (drift and framing there at `ranking.NEAR` 0.9 of their limits, as they hover around them): one that comes and goes stays in the row's `flags`, is left out of its `signs` (shown muted) and is named in the reasons (Mage-Flow LoRA at 200 epochs: faces x1.32-1.37 at epochs 75-100 only with the scenes intact, the only flag-free save was the last one, already speckled). SigLIP2 prompt following stayed flat in every run and the trigger already appears as text with the base model: neither decides a pick. Copying is a per-sample signal (`summary["dino_nearest_max"]`, DINOv2 similarity of the sample nearest to a training image, over `ranking.COPY_LIMIT` 0.80): one copied sample counts, as the LTX 2.3 runs' training scenes showed; the median never reached the old limit. The training data's surroundings in other prompts' scenes are a note, not a flag, and only with faces in the training photos (`scoring.person_patches` masks the person below the largest face; without one the whole image, a style's or an object's, would read as surroundings; `scene_nearest_train` is the DINOv2 cosine of the remaining patch tokens, each unit-normalized and averaged, to the nearest training background; paired rise `ranking.SCENE_NOTE` 0.12, recurring): in the LTX 2.3 and MiniMax H3 runs the training clip's garden came with the likeness and the judged best checkpoints carried it. Only where every save on the likeness level has signs does the note count, as one more sign from its first save, in the fewest-signs pick (Wan 2.2 T2I DoRA 2x: the training garden replaced the news studio from epoch 100 while epoch 125 lacked a recurring framing sign by chance; judged 25-75, picked 75 instead of 125, no other judged run moved). The framing and fewer-faces signs likewise need faces in the training photos: in a pet or object run the face detector finds dog faces and stray people (FLUX.2 Klein 4B on a corgi read as faces x5.5); there likeness, copying and variety all come from DINOv2 and rise together, and the plateau rule (the earliest save with the fewest signs) picked both judged object runs in range. Tests: `tests/test_best_checkpoint.py`, `tests/test_unified_ui.py::test_best_checkpoint_finder_*`.
- LoRA / DoRA (`adapter.py`): DoRA is the default Adapter Type (user decision, 2026-10-18: every LoRA training is DoRA; a loaded config without `use_dora` stays LoRA). Wan 2.2 runs that train the high- and low-noise experts together keep one DoRA magnitude per expert and save two files: `<name>.safetensors` for the low-noise model and `<name>_high_noise.safetensors` for the high-noise model (Guardrail 18). Adapter Type is not a trainer setting. It is appended after each backend's positional specs (`is_synthetic`), folded into Network Arguments (`use_dora=True`) for save, print command and Start in LoRA mode, and read back from them on load, so presets stay plain trainer configs. DoRA is the input-axis form (Guardrail 18; musubi `DoRAInputModule`, sd-scripts `networks/dora.py`), which ComfyUI and SwarmUI load like a LoRA; SECoursesAudioTools' `musubi_lora_keys.py` registers the trainer's layer names that ComfyUI V92 otherwise skips (Qwen-Image 2.1 MLP halves, Z-Image q / k / v, every HiDream-O1 layer); for stock ComfyUI and SwarmUI the Qwen-Image 2.1 trainer also writes `<name>.comfy.safetensors` with `transformer.` Diffusers keys (`QwenImage21NetworkTrainer.on_post_save`, `convert_lora.convert_to_diffusers`: ComfyUI maps the two halves onto its fused `img_mlp.gate_up` only for such keys, 7 of 7 layers instead of 5; `trainer_base.remove_model` removes the copy with old checkpoints). Network Arguments for DoRA: `use_dora=True` (input axis), `dora_axis=output` (PEFT `lora_magnitude_vector`, needs conversion for ComfyUI), `dora_detach_norm=True` (no gradient through the column norm, DoRA paper section 4.3: about half of DoRA's extra time), `dora_scale_lr_ratio=<x>` (learning rate of the magnitudes relative to the LoRA matrices). Eager DoRA is bound by op dispatch (`dont_upload/vram_lab/dora_overhead_bench.py` measures and profiles it), so keep the per-layer path free of no-op casts and views. Tests: `tests/test_unified_adapter.py`, `tests/test_kohya_dora.py`.

import gradio as gr
from musubi_tuner_gui.<trainer>_lora_gui import <trainer>_lora_tab
with gr.Blocks():
    <trainer>_lora_tab(headless=True, config={})
